# MES Master Data Seed Scripts

Run these scripts **in order** after the database schema has been created.

## Run Order

| # | File | Description | Dependencies |
|---|------|-------------|--------------|
| 1 | `01-asset-types.sql` | ISA-95 hierarchy levels | None |
| 2 | `02-state-types.sql` | Machine state categories | None |
| 3 | `03-count-types.sql` | Production counter types | None |
| 4 | `04-measurement-types.sql` | Process variable types | None |
| 5 | `05-downtime-reasons.sql` | Downtime reason codes | None |
| 6 | `06-product-families.sql` | Product categories | None |
| 7 | `07-product-definitions.sql` | SKUs | 06 (product_family) |
| 8 | `08-state-definitions.sql` | Granular states | 02 (state_type) |
| 9 | `09-kpi-definitions.sql` | KPI definitions | None |
| 10 | `10-asset-definitions.sql` | Equipment hierarchy | 01 (asset_type) |

## Verification

Run `99-verify-seed.sql` after all scripts to confirm the expected record counts.

## Notes

- All scripts are **idempotent** (safe to re-run)
- Uses `ON CONFLICT DO UPDATE` for upsert behavior
- No hardcoded IDs - all generated by PostgreSQL sequences
- Asset hierarchy uses `tag_path` as the natural key
